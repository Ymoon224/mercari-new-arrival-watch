# 远端服务改造需求与实现状态（v2.0.0）

记录日期：2026-10-20。

状态：**远端架构与插件管理功能代码已实现，尚未部署到远端服务器；日本服务器上的 Mercari HTTP 直连、响应稳定性和实际微信扫码推送验收待完成。** 本地测试与模拟响应不能替代目标服务器实测。当前版本 v2.0.0 保留本机旧模式，不迁移或修改已有本机微信绑定。

安装、HTTPS、持久数据和更新步骤见 [远端服务部署](远端部署.md)。

## 已实现：在插件中添加远端微信接收人

流程：**管理员在插件点击“添加接收人” → 服务器生成二维码 → 插件显示二维码 → 接收人使用手机微信扫码 → 服务器保存绑定。**

具体要求：

1. 扫码登录由远端服务器发起，使用服务器上的微信插件和转发服务。
2. 本机插件负责发起添加请求、展示二维码及登录结果，不要求管理员每次远程登录服务器执行添加脚本。
3. 微信登录凭证保存在服务器，不发送给本机插件，也不提交到 GitHub 仓库。
4. 绑定完成后，由管理员在插件中备注用户、分配监控关键词和检查间隔；新接收人不自动订阅已有任务。
5. 其他微信接收人只接收提醒和回复激活会话，没有修改关键词、间隔、屏蔽词或其他用户的管理权限。
6. 必要时在插件填写手机显示的数字配对码；状态分别显示等待扫码、手机确认、配对码、成功、失败、过期和取消。状态查询请求成功不表示绑定成功。
7. 当前本机的“添加微信接收人.cmd”继续用于本机模式；远端模式通过服务器官方登录流程绑定，不在本机执行这个脚本。

## 已实现：远端架构与管理边界

- 远端服务独立负责定时采集、上一轮商品码、配置、通知队列及微信推送；这些数据保存在仓库外的持久目录。部署目标为日本服务器，目前没有执行实际迁移或部署。
- 服务端直接通过 HTTP 获取搜索数据，不依赖本机或服务器上的浏览器定时打开网页采集。HTTP 采集代码和本地测试已实现；目标日本服务器上的接口可用性、稳定性、个人商品、Shops 商品及广告识别仍待实测验收。
- 插件作为管理员控制面板，管理关键词、标题屏蔽词、检查间隔、接收人、监控开始与暂停，并查看监控及推送状态。
- 插件关闭或本机关机后，服务器按已保存的配置继续运行。
- 暂停某个关键词后，服务器不再为该关键词发起 Mercari 采集请求；暂停全部监控后不再发起任何 Mercari 采集请求。已经发出的请求需要完成或取消。
- 管理接口在采集暂停时继续运行，以便插件查看状态和恢复监控。暂停采集与处理此前的微信待发消息分开控制。
- 插件填写服务器的 HTTPS origin 与管理员密钥。服务器通过 `MERCARI_ALLOWED_ORIGINS` 显式允许该插件 ID 对应的 `chrome-extension://...`。连接后面板显示远端模式、连接地址与服务状态，管理员可以确认连接目标；不允许接收人通过微信管理配置。
- 切换远端后，本机采集定时器、扩展自建采集标签与本机待发重试停止。本机配置单独保留，不自动上传；切回本机后需要管理员明确启用，避免同时监控。
- 从插件移除服务器连接只清除本机保存的地址与密钥，不暂停服务器。需要停止访问 Mercari 时应先使用“暂停全部采集”。

## 保留的商品判断规则

- 首轮只建立基线，不推送已存在的商品；更改关键词后重新建立基线。
- 每个关键词抓取指定数量的非广告商品，比较本轮与上一轮成功抓取的带类型商品 ID。只推送上一轮不存在、且标题未命中屏蔽词的商品。
- 不使用 7 天 ID 历史去重或店铺同标题／价格去重。只改变顺序或价格而 ID 不变时不推送；商品离开上一轮结果后再次进入，会再次提醒。
- 屏蔽词只过滤提醒，不改变用于比较的原始商品 ID 窗口，不因此额外访问商品详情或补抓更多结果。
- 抓取失败、数量不足或响应异常时保留旧基线。发现记录与通知投递分别持久保存；同一消息的网络重试沿用消息编号，避免重发已经确认成功的投递。

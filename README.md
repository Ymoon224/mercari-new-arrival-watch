# Mercari 上新提醒

当前代码版本为 **v2.0.0**，支持本机浏览器采集与远端 HTTP 服务两种模式。远端管理、关键词与屏蔽词、开始／暂停、状态查看及插件扫码添加微信接收人均已实现；**尚未部署到远端服务器，日本服务器上的 Mercari HTTP 直连实测仍待完成**。本地自动化测试不等于远端站点可用性验证。

Chrome / Edge 插件作为管理员面板。每个关键词独立设置检查间隔、扫描数、标题屏蔽词和微信接收人；各关键词只与上一轮成功抓取的**非推广商品** ID 比较，推送本轮新出现且未命中屏蔽词的商品，面板显示前 5 件。保留原本机模式，不会自动迁移现有配置或微信绑定到服务器。

部署步骤见 [远端服务部署](docs/远端部署.md)，实现范围与待验证项见 [远端服务改造需求](docs/远端服务改造需求.md)。

## 运行模式与远端连接

| 模式 | 采集与微信推送在哪里运行 | 本机浏览器能否关闭 |
|---|---|---|
| 本机浏览器采集 | 扩展创建自己的 Mercari 搜索标签，本机转发服务发送微信 | 不能；关闭浏览器后停止采集 |
| 远端服务采集 | 服务器直接通过 HTTP 采集并推送，插件只发送管理操作 | 可以；关闭插件、浏览器或本机电脑不影响服务器任务 |

远端服务按 [部署文档](docs/远端部署.md)安装后，在服务器的 `MERCARI_ALLOWED_ORIGINS` 中显式登记管理员插件 ID 对应的 `chrome-extension://...`，不能使用 `*`。插件重新安装导致 ID 改变时，需要更新允许来源并重启服务。

插件“运行位置”选择“远端服务采集”，填写 **HTTPS origin**（例如 `https://watch.example.com`，只含协议、域名及可选端口，不含 `/api`、查询参数或页面路径）和服务器管理员密钥。点击“连接服务器”并允许该地址的访问权限后，核对面板显示的“远端采集”模式、连接地址及服务状态，以确认正在管理的服务器。生产远端连接必须使用 HTTPS；`localhost` 或 `127.0.0.1` 的 HTTP 仅供本机开发测试。

连接远端后，插件停止本机采集定时器、自己的采集标签和本机待发重试；原本机关键词、上一轮 ID、历史、密钥和队列单独保留，不自动上传。远端配置和微信凭证保存在服务器，插件只保存管理地址和管理员密钥。切回本机不会自动恢复采集，需确认远端已经暂停，再明确启用本机，避免重复监控。

“暂停全部采集”停止新的 Mercari 请求并取消正在执行的采集；暂停单个关键词只影响该任务。管理接口和微信会话维护继续运行，已有微信待发消息独立处理。“移除本机连接”只清除插件保存的服务器连接，**不会暂停服务器任务**。

## 只比较上一轮结果

已移除 7 天商品 ID 历史去重、店铺同标题同价格去重及对应设置项，扩展与微信转发服务均不再执行这些过滤。连续出现在抓取结果中的商品保持安静；商品离开上一轮结果后再次进入，会生成新提醒。不同店铺商品 ID 即使标题、价格相同也会正常提醒。只改变顺序或价格而商品 ID 没变时，不产生上新提醒。

首轮仍只建立基线。升级会保留上一轮结果、关键词、间隔、用户分配、发现记录和待发消息，旧发现记录不会重新补发；旧版历史表及店铺去重配置会被清理。网络重试仍使用同一条消息编号，已经确认发送成功的消息不会因为重试而再发。

标题屏蔽词按每行一个设置，命中任一词时不推送该商品；按 NFKC 规范化并忽略大小写匹配标题。仍保留本轮原始非广告商品 ID 作为下一轮比较基线，不补抓额外商品、不访问商品详情。这与已移除的历史 ID／店铺内容去重无关。

## 安装插件与本机模式开始

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 打开「开发者模式」，点「加载已解压的扩展程序」。
3. 选择本项目的 **extension** 文件夹（包含 manifest.json 的那一层）。
4. 点击扩展图标，打开监控面板，确认“运行位置”为本机模式。可先点「测试本机通知」。使用服务器则按上文和 [远端部署文档](docs/远端部署.md)连接。
5. 本机模式在关键词列表中开始相应关键词的监控。首轮只建立基线，不推送已有商品；首次采集通常需要数秒至一分钟。

**本机模式**需要浏览器和电脑保持运行；关闭浏览器、断网、电脑休眠时不会正常检查。正常重启浏览器后恢复本机已启用的监控；从远端切回本机仍需明确启用。浏览器调度并非精确计时器，可能晚于设置的检查时间。远端模式不受本机浏览器运行状态影响。

## 多关键词与独立间隔（v1.2.0）

- 点击「＋ 添加关键词」，输入关键词、检查间隔和扫描数，勾选是否启用后保存。最多添加 20 个关键词，间隔支持 1–1440 分钟的整数。例如「潔世一」每 1 分钟，「凪誠士郎」每 5 分钟。
- 点击关键词卡片，查看该词的最新 5 件、发现记录、异常次数与待发队列；右侧可以修改其间隔和扫描数。各词可单独开始、暂停或删除。
- 本机模式升级时自动迁移原关键词、上一轮结果、发现记录、待发队列、连续异常次数和微信密钥；不会自动导入远端。调整间隔会保留上一轮结果；更改关键词会重新建立基线。
- 所有关键词共用一套通知配置，推送标题注明对应关键词。不同关键词的上一轮结果和连续异常计数分别保存；同一商品同时匹配两个词时，可能收到两条分别注明关键词的消息。
- 本机调度器每分钟检查哪些关键词到期，只为到期的关键词抓取商品。同一关键词不会同时运行两轮，本机最多并行检查 3 个关键词；繁忙时其余任务排队，空闲后继续。休眠后恢复只检查当前结果，不补跑休眠期间的每一轮。远端由常驻服务独立调度，默认单任务采集，并设全局请求间隔；见部署配置。
- 连续失败超过 5 次的提醒也按关键词分别触发。本机后续采集按该词的间隔重试；远端失败采用退避，遇到明确访问限制可暂停任务等待管理员处理。暂停关键词后，已有待发消息仍会重试。

页眉显示 **v2.0.0**。更新插件后请在扩展管理页重新加载原扩展，并关闭旧面板再重新打开。本机模式升级保留原有微信绑定；新服务器没有本机凭证，需要在服务器重新绑定，详见部署文档。

## 删除接收人与停止连接（v1.3.1）

在“微信接收人管理”中点对应用户的“删除用户”，核对备注后确认。服务端会先撤销此用户的推送资格，再停止其消息收取和发送、移除服务所在机器的微信登录及账号索引。该用户会从对应模式的关键词任务和待发消息接收人中移除；共享任务的其他用户继续接收。仅剩此用户且没有本机通知的任务自动暂停。

原有待发队列移到 `deleted-queues` 归档，不再发送。删除记录会持久保存，重启、旧版扩展和同步旧登录均不能恢复此用户；重新扫码取得新凭证后，可以由管理员重新导入为新用户，需要重新分配关键词，不继承已删除用户的任务。

多用户连接提示会注明具体异常的接收人和该用户的待发数量，不再把某位用户登录失效笼统显示为全部微信推送未恢复。其他会话可用用户仍独立发送；每条消息的发现时间间隔也不等于在发送队列中的等待时间。

默认**不发送**停用消息。管理员可勾选“删除前通知用户”，在停止连接时尝试发送一次固定停用说明；只有微信接口接受才显示“已接受”，不保证手机显示。登录已失效时不能发送，会话次数不足或网络异常时也可能失败。通知失败不阻止删除，重启不会补发或重复发送停用通知。

服务会尽力调用官方 `notifyStop`。该接口在[官方协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)中只表示“客户端停止”，不是已确认的远程解绑或 token 撤销接口。不能保证微信客户端的绑定入口消失，也没有官方保证的自动停用系统通知。要解除微信端显示的绑定，应由接收人在微信中操作。管理员删除仍会立即阻止此用户继续使用对应服务的上新提醒；回复“继续提醒”不会恢复已删除资格。

## 多位微信接收人，由你统一管理（v1.3.0）

关键词、屏蔽词、检查间隔、扫描数、接收人分配和开关只通过管理员插件面板管理。其他微信用户只接收提醒、回复消息激活会话，没有关键词设置入口；微信聊天正文不作为管理命令执行，也不交给大模型。插件中的管理员连接密钥不会交给微信接收人。远端管理接口也必须验证服务器管理员密钥和已允许的插件来源。

**远端模式**：管理员在插件点击“扫码添加接收人”，插件展示服务器发起的官方二维码；接收人手机扫码并确认，必要时在插件填写手机显示的数字配对码。服务器保存登录凭证，绑定完成后仍需分配关键词；失败、取消、过期不会显示为绑定成功。完整步骤见 [远端服务部署](docs/远端部署.md)。

**本机模式**沿用以下步骤：

1. 在本机双击 `D:\OpenClaw\mercari-bridge\添加微信接收人.cmd`，让新增接收人使用自己的微信扫码授权。每个用户分别绑定一次。
2. 打开扩展面板的“微信接收人管理”，点“同步已绑定用户”。为新用户设置备注，便于区分。最多 20 位接收人。
3. 在每条关键词任务的“接收此关键词的微信用户”中勾选接收人并保存。新用户不会自动订阅已有任务。旧任务默认仍发给“我的微信”。
4. 同一任务可以选择多人，他们接收相同关键词和间隔的提醒；不同用户需要不同间隔时，可以建立同关键词、不同接收人的独立任务。相同关键词的多个任务不能包含重复的接收人。
5. 新用户在微信给 ClawBot 发一条消息，建立自己的发送会话。会话次数用尽后，也由各自回复消息恢复；回复不会修改监控配置。

每位接收人分别保存会话、次数、发送记录和待发队列。一位用户受限不会挡住其他用户。暂停用户的“允许接收”会保留其待发消息，重新允许后继续补发。修改任务接收人只影响之后发现的消息，已经生成的待发消息仍按生成时的接收人列表处理，避免转发给后来加入的用户。

本机转发服务只监听本机；远端服务默认监听服务器回环地址，由 HTTPS 反向代理开放已认证的管理 API。不向接收人开放管理页面；接收人导入、备注和接收开关均需管理员密钥。此版不提供接收人自行登录的管理账户或微信关键词管理命令；其他用户无需安装 Codex 或浏览器扩展。

本机模式原微信继续使用原 `deliveries.json`；其他用户的队列保存在 `D:\OpenClaw\mercari-bridge\queues`，用户对应关系保存在同目录 `recipients.json`。本机更新脚本会先备份这些文件，不改变原微信绑定和管理员连接密钥。远端使用独立持久数据目录，不能用代码更新覆盖该目录。

## 微信恢复与重复提醒修复（v1.2.1）

- 微信返回 `-2` 时记录“发送受限”，保留待发消息，暂停向失效会话发送。收到扫码用户的一条新消息、或 Gateway 更新了会话后立即恢复重试，不再等原先的数分钟退避。拒绝状态会保留到磁盘，重启服务不会误显示已恢复。
- 面板顶部显示微信错误和对应服务的待发数量；“已保存会话”与“最近发送请求已被微信接受”分开显示。“重试微信待发消息”按钮只重试未完成消息，不会生成新测试消息或重发已成功的批次。
- 积压的短消息自动合并到约 2,700 字以内的摘要，保留各批的关键词、标题、价格和链接，减少微信请求次数。合并任务先落盘；失败或重启后使用同一消息编号重试，成功后一起确认对应原始批次。已经发出部分分段、或发送结果不确定的网络失败消息不会重新合并。
- 当前版本的扩展和微信队列均不按历史商品 ID、店铺标题或价格过滤新的发现消息。转发服务仅按消息编号记录交付进度，避免同一条消息因网络重试而再次发送。
- 微信官方接口存在会话时效和主动发送次数限制。本次实测新会话连续 10 次请求成功，第 11 次返回 `-2`，与[腾讯官方仓库中关于 10 条限制的反馈及回复](https://github.com/Tencent/openclaw-weixin/issues/202)一致。服务每次新会话按 10 次计算，在最后一次发送中附上回复激活的提示，随后等待用户互动；计数会持久保存，重启不会重置。合并后的多批摘要只消耗一次请求。当前接口没有可靠的自动续期保证，不能保证无需微信端互动就一直主动推送。具体会话有效时长不作假设。

## 个人微信推送

### 本机模式：微信 ClawBot

远端模式请使用 [远端服务部署](docs/远端部署.md)中的安装与扫码流程。以下说明保留本机已有部署方式：已安装 OpenClaw、腾讯官方 `@tencent-weixin/openclaw-weixin` 插件并扫码登录后，使用本机转发服务连接扩展。它复用官方插件的收发接口和登录文件，只向扫码用户发送消息，不需要大模型 API。

1. 启动 `D:\OpenClaw\mercari-bridge\启动微信转发.cmd`。此服务在后台运行，程序、配置、临时数据和待发队列都在 D 盘。电脑重启后需再次启动。
2. Chrome / Edge 扩展管理页重新加载本项目的 `extension` 文件夹，确认版本 **2.0.0**，并选择本机采集模式。更新原扩展可保留其监控历史。
3. 打开 [本机连接页面](http://127.0.0.1:17869/setup)，复制连接密钥。
4. 在提醒面板选择 **微信 ClawBot（本机 OpenClaw）**，粘贴连接密钥，保存并允许访问本机服务，然后点「测试微信」。若旧渠道还有未发消息，先核对记录并清除旧待发队列再切换。
5. 手机微信若未收到消息，先给 ClawBot 发一条「上新提醒」，等待数秒后检查连接页和提醒面板显示的待发数量、错误原因。首次建立会话、会话过期或微信拒绝发送时，仍需要用户在微信内发送消息或重新扫码。
6. 微信测试成功后，开始所需关键词的监控。每个关键词首轮只建立基线，之后仅对新出现的非推广商品发消息。

浏览器向 `127.0.0.1:17869` 提交消息编号、商品标题、价格、链接和接收人。转发服务持久化后再确认接收，随后通过官方微信接口发送；网络失败按间隔重试，会话明确被拒绝时等待新消息刷新。服务重启后继续处理，已成功的分段不重复发送。接口返回成功代表接受请求，需要在手机核对实际送达；极端情况下在发送成功与落盘之间崩溃仍可能重复。

微信登录凭证留在 `D:\OpenClaw\data\openclaw-weixin`。扩展只存本机连接密钥，不需要复制微信 token。服务只监听本机地址，验证来源、连接密钥和消息格式，不开放局域网端口。

服务可在 Gateway 未启动时独立收取会话上下文；不保存收到的聊天正文，也不调用大模型。如果完整 OpenClaw Gateway 正在运行，则使用它已保存的会话上下文，避免两个收信循环同时轮询。停止服务使用同目录的 `停止微信转发.cmd`，待发消息保留。

开发安装或更新服务（先停止已有服务）：

```powershell
& .\tools\install-mercari-bridge-d.ps1
& D:\OpenClaw\mercari-bridge\start.ps1
```

`bridge` 目录是服务源代码，安装器复制到 D 盘运行。`config.json`、`deliveries.json`、`service.log` 和 `service-error.log` 均在安装目录，不打包到浏览器扩展。

### 本机模式：原有第三方渠道

仍保留以下旧渠道兼容已有配置，当前 ClawBot 接入不使用它们。服务条款、免费额度和送达方式以各官网为准。

- **Server酱 Turbo**：[获取 SendKey](https://sct.ftqq.com/docs/getting-started/sendkey/)。使用 SCT 开头的 SendKey；此版不接 Server酱³ 的独立 App 密钥。
- **PushPlus**：[官网](https://www.pushplus.plus/)、[消息接口文档](https://www.pushplus.plus/doc/guide/api.html)。获取个人 token 并确认微信接收渠道已绑定。

在面板选择渠道、填入密钥、保存配置。浏览器会请求访问对应推送服务的权限。点「测试微信」，并在微信里确认收到。服务接口返回成功仅代表接受消息，不保证已经送达。

密钥保存在本机扩展存储，配置界面不会回显，留空会保留同渠道的旧密钥。无需将密钥发给他人。商品名称、价格和链接会发往所选服务；密钥不会发给 Mercari，也不会写进通知或日志。

## 比原始“只比较 5 个 ID”方案改进了什么

- 每个关键词每轮默认读 20 件，前 5 件用于展示；可选 5 / 20 / 50 / 100。只比较 5 件无法覆盖一个检查间隔内超过 5 件上新的情况。
- 使用带类型的键 `item:m…` / `product:…`，不按商品码的大小推断时间。
- 本机模式只读当前搜索结果的普通 `li[data-testid="item-cell"]`；广告组件、广告参数链接和黄色闪电角标被排除。远端模式解析 HTTP 搜索响应中的商品与广告标记，不打开浏览器。个人商品及 Shops 都使用带类型的商品 ID；HTTP 可用性与广告标记仍需在目标日本服务器实测。
- 每个关键词仅保存上一轮成功抓取的商品 ID 作为比较基线，不使用 7 天 ID 历史或店铺内容去重。本轮不在上一轮结果中的 ID 都会提醒，上一轮仍在的 ID 只改变顺序时保持安静。
- 首次运行只建立基线。改关键词后重新建立基线，避免推送旧结果。
- 抓取不足、页面缺失、加载失败等均保留旧基线。本机按对应关键词间隔重试；远端采用退避，并对明确限制暂停，避免持续重试放大访问量。
- 监控连续失败超过 5 次（第 6 次）时，通过已选择的微信渠道及本机模式启用的浏览器通知发送一条异常提醒，包含检查时间、最近错误和上次成功时间。加载超时、采集失败及本机监控标签页意外关闭／创建失败都计入；通知服务自身失败不计入采集失败次数。
- 同一段连续异常只生成一次提醒；失败计数和提醒标记保存在实际执行监控的位置，重载不会反复提醒。成功抓取后清零，之后再次连续失败 6 次可以重新提醒。断网时消息先排队，网络与微信连接恢复后补发。明确限制导致任务自动暂停时，处理后需要管理员恢复。
- 通知采用持久化待发队列。一个渠道失败时下轮重试，不重复发送已经成功的另一个渠道。
- 监控正常且没有新出现的 ID 时保持安静。暂停后保留上一轮结果，恢复时继续比较。

**监控的含义是“相对上一轮搜索结果新出现的商品”**。搜索索引可能延迟或重新排序。商品离开结果后重新进入，以及下架商品后从尾部补进来的旧商品，也会按新出现的商品提醒。仅凭搜索结果 ID 无法确认真实上架时间。大量上新挤出整个扫描窗口时会显示“与上一轮无重叠”提醒，无法保证完整捕获；可增加扫描数。

更改扫描数会继续沿用上一轮结果；扩大范围后，新进入比较范围的商品也可能触发提醒。更改关键词会重建对应模式下该任务的基线和记录。

通知成功与本地确认之间若浏览器意外退出，极少数消息可能重发。微信服务额度不足时消息会留在待发队列；可在面板清除队列，发现记录不会被删除。

## 当前状态与权限

扩展首次安装时本机默认关键词**暂停**；升级保留原有开关。远端首次启动没有关键词或接收人，需管理员配置。代码准备好不代表已经部署或开始持续监控；开始相应关键词的监控才会抓取。微信 ClawBot 需要执行服务的机器上已登录的官方插件和相应管理员连接。

固定权限：Mercari 页面访问、定时器、本机存储和浏览器通知，用于兼容本机模式。服务器 HTTPS、本机转发服务、旧微信服务的访问均是按需申请的可选权限；连接时仅请求所填服务器地址。不读取浏览历史，不修改商品，不购买商品，不操作微信客户端。

本机模式扩展只创建、滚动和关闭自己的后台监控标签，不刷新用户正在使用的标签；远端模式不创建这些标签。若遇验证码或站点限制，应查看错误、暂停或降低频率；程序不绕过验证。若页面或响应结构改变，采集器可能需要更新。

## 开发验证

扩展与本机转发本身不需额外安装 npm 依赖；本机服务复用已安装的腾讯微信插件，远端需按部署文档安装固定版本官方运行依赖。二维码编码器已随扩展打包，见 `extension/qr-code.LICENSE.txt`。核心逻辑、通知队列、本机接口及远端管理／采集测试：

```powershell
node --test tests/*.test.mjs
```

`tools/browser-check.mjs` 使用 Playwright 做 DOM 集成验证和多关键词面板操作测试，不加载个人浏览器资料、不发送真实微信消息。可用 `PLAYWRIGHT_MODULE` 指定本机已有 Playwright 的入口文件，用 `BROWSER_EXECUTABLE` 指定 Chrome / Chromium 可执行文件；本机已安装的 OpenClaw 自带 `playwright-core`，可复用其 `node_modules/playwright-core/index.mjs`。

无 Playwright 时也可运行 `python tools/preview_server.py`，用浏览器打开 `http://127.0.0.1:8769/collector-test` 检查 `passed: true`。同地址的 `/dashboard.html` 是带本地模拟数据的面板预览，不会开始监控或发送通知。此预览服务器仅用于开发，正式安装运行不需要它。

本机采集器的 DOM 定位来自实际搜索页与公开前端脚本核对；`tests/fixtures/search.html` 覆盖普通商品、Shops、广告卡片、黄色角标、重复链接及尚未加载的占位卡。远端 HTTP 采集与管理接口有独立本地测试，日本服务器实测状态见上文与部署文档。

`sample-observation.json` 保存开发过程中从实际搜索页读到的一组前五商品，仅作验证记录；安装后重新建立基线，避免把这份观察记录当作实时数据。
